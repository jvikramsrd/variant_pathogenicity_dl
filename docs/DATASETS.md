## 1. ClinVar `variant_summary` (NCBI)

* **URL**: <https://ftp.ncbi.nlm.nih.gov/pub/clinvar/tab_delimited/variant_summary.txt.gz>
* **Local copy**: `data/raw/variant_summary.txt.gz`
* **Content**: one row per ClinVar allele (~2M rows), tab-delimited, gzip.
* **Licence**: US-government work, public domain.
* **Downloaded**: cached from previous run; SHA-256 recorded in manifest.json.

### Processing rules (`src/data_loader.py`)

1. Streamed in 200k-row chunks (one pass serves **all** requested genes via
   `build_multi_gene_dataset`; per-gene passes were O(n·genes)).
2. Gene filter: case-insensitive exact match on `GeneSymbol`.
3. Keep only single-residue missense substitutions:
   * `ProteinChange` matching `^([A-Z])(\d+)([A-Z])$`, or
   * three-letter HGVS-p embedded in `Name` (`p.(Arg273His)` style);
     frameshift/extension forms are rejected by a `(?![a-z])` guard.
4. Significance mapping:
   * `{pathogenic, likely pathogenic}` → `label = 1`
   * `{benign, likely benign}` → `label = 0`
   * `uncertain significance` → VUS holdout (`label = NaN`)
   * anything containing `conflicting` or mixing categories → dropped.
5. Review stars (`REVIEW_STATUS_STARS`): practice guideline=4 … single
   submitter=1; labelled variants below `min_stars` (default 1) are dropped;
   VUS kept regardless of stars.
6. De-duplication per `(gene, hgvs_p)`: highest-star assertion wins.
7. Alignment validation against the UniProt canonical sequence
   (`src/esm_extractor.validate_and_align`): position within range AND wt
   residue equal to the sequence residue — protects against isoform drift.

### Output schema (per gene, `FINAL_COLUMNS`)

`gene, position (1-based int), wt_aa, mut_aa, hgvs_p, label {0,1}, review_status`

Files: `data/processed/{GENE}_labeled_variants.csv` and
`{GENE}_vus_variants.csv`.

### Caveats

* ClinVar labels inherit submitter quality variance; star filter mitigates it.
* Benign classes skew towards common variants; class imbalance handled at
  training time (focal loss / weighted BCE).

## 2. ProteinGym v1.3 — DMS substitutions

* **URLs**:
  Harvard mirror: <https://marks.hms.harvard.edu/proteingym/ProteinGym_v1.3/DMS_ProteinGym_substitutions.zip>
  Zenodo DOI record: <https://zenodo.org/records/15293562>
  GitHub: <https://github.com/OATML-Markslab/ProteinGym>
* **Version**: v1.3 (2025-04-27 Zenodo update).
* **Licence**: MIT (repository).
* **Citation**: Notin et al., *ProteinGym: Large-Scale Benchmarks for Protein
  Fitness Prediction and Design*, NeurIPS 2023 (Datasets & Benchmarks).
* **Content**: 217 deep mutational scanning assays, ~2.5M mutants; each assay
  CSV holds `mutant` (e.g. `A119D`), `mutated_sequence`, continuous
  `DMS_score`, assay-binarised `DMS_score_bin`.
* **Reference file**: `DMS_substitutions.csv` maps every `DMS_filename` to
  `UniProt_ID`, taxon, `target_seq`, binarization cutoff/method, first author,
  year, selection type, MSA stats.

### Processing rules (`src/external_datasets.load_dms_assays`)

1. Reference filtered to `taxon contains "human"`.
2. Each assay CSV parsed inside the zip; `mutant` tokens regex-parsed to
   `(wt, pos, mut)`; synonymous (`wt==mut`) and stop-codon tokens dropped.
3. Restricted to panel accessions; **wt residue validated against the
   canonical UniProt sequence** — assays using isoform numbering that does not
   match canonically are dropped and counted (`stats.dms_rows_dropped_wt_mismatch`).
4. `hgvs_p` synthesised as three-letter HGVS.

### Outputs

* Long table: `data/processed/extended/dms_scores_long.csv`
  columns `uniprot_id, dms_id, taxon, wt_aa, position, mut_aa, mutant,
  hgvs_p, dms_score, dms_bin, first_author, year, selection_type`.
* Master-table aggregates (median score/bin, `n_dms_assays`, pipe-joined ids).

### Caveats

* `DMS_score` directionality differs per assay (higher = fitter usually, but
  check `raw_DMS_directionality` in the reference); we therefore keep raw
  scores and never mix them into a global scale without normalisation.
* `DMS_bin` thresholds are assay-specific (`DMS_binarization_cutoff/method`).

## 3. ProteinGym v1.3 — clinical benchmark

* **URL**: <https://marks.hms.harvard.edu/proteingym/ProteinGym_v1.3/clinical_ProteinGym_substitutions.zip>
* **Content**: 2,524 CSVs named by RefSeq protein accession (`NP_000007.1.csv`);
  columns include `protein_sequence`, `mutant`, binary `DMS_bin_score`
  derived from clinical annotation curation.
* **Role in our pipeline**: independent second opinion on clinical labels +
  coverage for panel proteins whose variants our direct ClinVar parse may
  treat differently (e.g. different transcript mapping).

### Processing rules

1. All CSVs parsed, tokens validated as in §2.
2. `DMS_bin_score` holds **string class labels** — `{"Pathogenic", "Benign"}`
   (vocabulary verified across the bundle) — mapped to `{1, 0}`; any other
   string is dropped and counted.
3. One representative `protein_sequence` retained per NP_ accession
   (`out.attrs["np_sequences"]`).
4. **RefSeq→UniProt mapping by exact whole-protein sequence equality**
   (`map_np_to_panel`) against panel canonical sequences. Exactness guarantees
   identical residue numbering; near-matches are discarded and counted in the
   manifest (`clinical_np_matched/unmatched`).
5. wt-vs-sequence validation repeated post-merge.

### Caveats

* The benchmark's labels are themselves curated from ClinVar/HGMD-like
  evidence; we use them as a *separate column*, never silently overriding
  ClinVar (see §9 precedence).

## 4. ProteinGym v1.3 — zero-shot clinical model scores

* **URL**: <https://marks.hms.harvard.edu/proteingym/ProteinGym_v1.3/zero_shot_clinical_substitutions_scores.zip>
* **Content**: same 2,524 proteins; per-variant scores of published
  predictors aligned with the clinical benchmark rows.
* **Columns kept** (`ZERO_SHOT_MODEL_COLUMNS`):
  `EVE, TranceptEVE_L, GEMME, ESM1b, PoET, REVEL, CADD, MetaRNN, VEST4,
  BayesDel (addAF), MPC, SIFT4G, PolyPhen2 (HVAR), Provean, FATHMM,
  DEOGEN2, MutationAssessor` → renamed to snake_case with `zs_` prefix
  (e.g. `zs_polyphen2_hvar`, `zs_trancepteve_l`).
* **Use**: optional MLP input features (`--extra_features zeroshot|all`)
  and baselines. Missing scores are median-imputed per column (priors are
  label-independent ⇒ no target leakage), remaining NaN → 0.

### Caveats

* These scores come from models trained on overlapping evolutionary data;
  they are priors/baselines, not independent test labels.
* Column availability varies slightly per protein; missingness logged.

## 5. AlphaMissense aa-substitutions (2023)

* **URL**: <https://storage.googleapis.com/dm_alphamissense/AlphaMissense_aa_substitutions.tsv.gz>
* **Version**: release of 2023-09-18 (`AlphaMissense v1`), Google DeepMind.
* **Licence**: **CC BY-NC-SA 4.0** — non-commercial use only; keep this
  constraint if redistributing derivatives.
* **Citation**: Cheng et al., *Accurate proteome-wide missense variant effect
  prediction with AlphaMissense*, Science 381 (2023).
* **Content**: every possible single-residue substitution across the human
  proteome keyed by UniProt accession:
  `uniprot_id \t variant (e.g. M1F) \t am_pathogenicity \t class`.
  1.21 GB compressed / ~9 GB uncompressed, no header (licence comment lines
  start with `#`).

### Processing rules

1. Full archive cached once under `data/raw/alphamissense/`.
2. `stream_filter_alphamissense` scans once, keeps only panel accessions,
   validates tokens, writes `alphamissense_subset.csv`
   (`uniprot_id, mutant, wt_aa, position, mut_aa, am_pathogenicity, am_class,
   hgvs_p`).
3. wt-vs-canonical validation applied after filtering.

### Caveats

* AlphaMissense scores should be treated as a *prior*, not ground truth;
  they correlate strongly with evolutionary conservation.
* Non-commercial licence restricts redistribution of merged outputs.

## 6. UniProt KB domain annotations

* **REST**: `https://rest.uniprot.org/uniprotkb/{accession}.json`
* **Licence**: CC BY 4.0.
* **Kept feature types**: `Domain`, `Region`, `Family`, `Coiled coil`,
  `Compositional bias`.
* **Output**: `uniprot_domains.csv` =
  `uniprot_id, feature_type, description, start, end` (1-based inclusive).
* **Derived feature**: `in_domain ∈ {0,1}` plus `domain_names` per variant
  position in the master table.

## 7. UniProt canonical sequences

* Resolved via REST search `(gene_exact:{symbol}) AND organism_id:9606 AND reviewed:true`;
  FASTA fetched per accession.
* Cached: `data/processed/extended/panel_sequences.{json,fasta}`.
* Used for: wt-alignment validation of every source, sliding-window ESM-2
  embedding, and RefSeq NP_-matching (§3).

## 8. Extended master dataset schema

`data/processed/extended/extended_dataset.csv` — one row per unique
`(uniprot_id, position, mut_aa)` substitution across the panel.

| Family | Columns | Notes |
|--------|---------|-------|
| keys/meta | `gene, uniprot_id, position, wt_aa, mut_aa, hgvs_p` | |
| supervision | `label` | resolved per §9 |
| | `clinvar_label, stars, review_status` | raw ClinVar assertion |
| | `clinical_label, np_accession` | ProteinGym clinical benchmark |
| DMS | `dms_score_median, dms_bin_median, n_dms_assays, dms_ids, dms_selection_types` | aggregated over covering assays |
| AlphaMissense | `am_pathogenicity, am_class` | |
| structure | `in_domain, domain_names` | from UniProt features |
| zero-shot | `zs_*` (17 columns) | §4 |
| provenance | `sources, n_sources` | pipe-joined tags |

Auxiliary tables alongside: `dms_scores_long.csv`, `pg_clinical_panel.csv`,
`zeroshot_scores_subset.csv`, `alphamissense_subset.csv`,
`uniprot_domains.csv`, `panel_sequences.fasta`, `manifest.json`.

## 9. Label precedence & conflict policy

```
label = clinvar_label                      if present
      = pg_clinical_label                  else if present
      = dms_bin_median                     else if n_dms_assays == 1
      = NaN                                otherwise (unsupervised row)
```

Rationale: curated clinical assertions carry the strongest semantics; the
ProteinGym clinical benchmark is an independent re-curation; DMS bins measure
*functional* effect, which need not equal pathogenicity, hence only when there
is exactly one assay (multi-assay disagreement keeps the row unlabelled).
All raw columns remain available for custom training schemes (e.g. regression
on `dms_score_median`).

## 10. Leakage controls

* Cross-validation groups are `"{uniprot_accession}:{position}"` strings —
  all variants of one residue of one protein stay in a single fold
  (`src/dataset.make_position_group_folds(groups=...)`).
* StandardScaler fitted on training folds only.
* External priors joined onto rows are label-independent; their imputation
  medians derive from external predictions, never from `label`.
* Optional stricter regime (not enabled by default): leave-one-protein-out
  evaluation can be run by grouping solely on `uniprot_id`.

## 11. Considered but rejected sources

| Source | Reason for rejection |
|--------|----------------------|
| dbNSFP 4.x | ~30 GB unpacked; overlaps almost fully with the zs_* columns already obtained via ProteinGym |
| gnomAD v4 allele frequencies | Hail/table toolchain too heavy for this repo; frequency-based benignness mostly redundant with ClinVar benign set here |
| EVE default repo files | ships MSAs/labels only, no ready scores; EVE scores already included via ProteinGym bundle |
| MaveDB | requires per-experiment registration/API scraping; ProteinGym covers the major assays |
| CADD genome-wide TSVs | registration wall + huge files; CADD already present among zs_* columns |

## 12. Reproduction commands

```bash
# 1. fetch/process everything (idempotent, resumable caches)
python scripts/build_extended_dataset.py                 # default 10-gene panel
python scripts/build_extended_dataset.py --no-alphamissense   # lighter build

# 2. unit tests for parsing/splitting logic
python tests/test_datasets.py

# 3. train with pooled genes and all prior features
python main.py --gene TP53,BRCA1,PTEN --extra_features all \
       --esm_model facebook/esm2_t33_650M_UR50D
```
